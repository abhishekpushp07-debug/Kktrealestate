## Decisions

- **`drizzle.kkt_schema_files`** lives in schema `drizzle` (next to drizzle's journal): reset drops it, test truncation and backups of
  `public` never touch it. Hand-written files re-apply when a new drizzle migration was applied too, because the updated_at /
  version triggers must cover new tables; the trigger file only creates missing triggers, so that costs no locks.
- **Indexes are declared in the Drizzle schema** and removed from the generated SQL, so the snapshot knows them and drizzle-kit reports
  no drift, while the online file builds them.
- **Migration waiters poll** `pg_try_advisory_lock`: with a blocking `pg_advisory_lock` the three-concurrent-migrators test hung
  forever (the waiters' snapshots blocked CREATE INDEX CONCURRENTLY).
- **`ValidationIssue.path` stays a string** (dotted path) — the task sketched `path: [field]`, but `ValidationIssueSchema`, the schema
  failure mapping and the ERP form mapper all use a string; one shape matters more than the array form.
- **MoneyError → 422 `INVALID_AMOUNT`, not 422 VALIDATION_ERROR**: the registry maps one status per code (VALIDATION_ERROR is 400) and
  the registry test enforces it. The details carry `issues` exactly like a validation error.
- **Unknown or 23505 errors**: only 23505 not translated by a route is mapped (409 DUPLICATE); everything outside 22/23 stays 500.
- **IN_USE usage_count** is counted after the transaction rolled back (bounded catalog + count query), falling back to 1.
- **Version ETags never answer 304**: many single resources carry derived fields (summaries, joined names) that change without a
  version bump, so a 304 on the version tag would serve stale money.
- **Version check order**: PATCH/DELETE are checked before the handler (so a version-less DELETE of a foreign or missing row is 428,
  which reveals nothing); POST actions check in the handler, after their own 404/409 guards where those came first (e.g. IN_USE on
  deactivate still answers without a version).
- **`@fastify/etag` removed** from apps/api (replaced by plugins/etag.ts); lockfile updated with `pnpm install --offline`.
- **ERP**: only the two exhaustive ledger-event maps were touched (typecheck). Sending If-Match on the newly required routes is the
  frontend track's work (list above).
