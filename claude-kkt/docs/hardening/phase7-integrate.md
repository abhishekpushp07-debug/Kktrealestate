## Decisions

- **Probes are matched by URL** (`/health`, `/health/live`, `/health/ready`, `/ready`, with or without `/api/v1`) and skip the
  public limiter entirely: a 429 on a probe restarts or unrouts a healthy instance; probes do no work worth limiting.
- **The internal budget applies only to a valid token WITHOUT `x-kkt-client-ip`.** With a visitor IP the visitor's bucket applies
  (C3 unchanged); without a valid token nothing changes. 6000/min per route group is far above ISR's rate and still a bound.
- **Erased idempotent responses keep their key** (body replaced, status kept) instead of deleting the row: deleting would let a retry
  of "create customer" run again after the erasure; 410 GONE says "done, but the data is gone — look it up".
- **BACKUP_EXPORT is not checkpointed**: the archive is one REPEATABLE READ snapshot of the tenant; a resumed build would mix two
  snapshots and restore incoherently. It now honours its abort signal (prompt drain), and the next attempt starts a fresh snapshot.
  LEDGER_REBUILD and REENCRYPT_FIELDS are idempotent per row, so resuming after the last finished batch is exact.
- **`CHECK_FAILED` is a finding, not a job failure**: the nightly report must still show every other booking's findings; the failing
  booking is listed (code + safe message, not repairable) and the KktIntegrityFindings alert fires because the run is not ok.
- **SLA backfill uses `updated_at`** as the pause start (the last change of a ticket waiting on the customer is, at the latest, when it
  entered that status or a later message); idempotent because the API always sets `sla_paused_at` on entering the status.
- **Contract coherence:** `PortalLoginSchema` / `PortalRefreshSchema` now alias the auth.ts schemas the API validates, so the portal
  contract cannot drift again. The ERP keeps offset paging (no cursor mode), so INVALID_CURSOR only needs copy.

## Contract shapes for other tracks / the frontends

- `GET /api/v1/portal/bookings/:id/ledger` → list envelope of `PortalLedgerRow` (current epoch only) + `summary: {cash_due_paise,
account_due_paise, total_due_paise, other_charges_due_paise, cash_paid_paise, account_paid_paise}` (`LedgerTotalsSchema`).
- `GET|PATCH /api/v1/portal/profile` → `PortalProfileResponse` + `version: int` (ETag `"v<n>"`; send `If-Match: "v<n>"`).
- `PortalLoginSchema` = `PortalAuthLoginSchema` (`company?`), `PortalRefreshSchema` = `PortalAuthRefreshSchema` (`refresh_token?`).
- `IntegrityFindingType` += `CHECK_FAILED`; `IntegrityCounts.CHECK_FAILED` (default 0).
- Idempotent replay of a record withdrawn by an erasure: **410 `GONE`**, `details: {original_status}`.
- CORS: credentialed for `ERP_ORIGIN`, `WEB_ORIGIN`, `PORTAL_ORIGIN`; request headers += `X-KKT-Session`, `X-KKT-Company`.
- Public limits: probes unlimited; valid internal token without `x-kkt-client-ip` → bucket `pub:<group>:internal`,
  `INTERNAL_RATE_LIMIT_PER_MIN` (6000).
- `GET /api/v1/public/media/:id?variant=` stand-in: `Cache-Control: public, max-age=60`.
- Jobs: LEDGER_REBUILD checkpoint `{after, result}`; REENCRYPT_FIELDS checkpoint `{pass, table, last_id, updated, failed, rehashed}`;
  export job result `{export_id, withdrawn: true, rows}` when an erasure withdrew it mid-build.
