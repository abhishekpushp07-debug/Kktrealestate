## What changed in the hardening round (phase 5)

Foundation (config, constraints, indexes, error registry), five tracks — security & privacy, money rules, platform reliability,
deployment & observability, frontend quality — each adversarially reviewed, an integration stage that wired the three front ends to
every new capability and fixed cross-track defects, and a verify stage (format/lint to zero, module boundaries enforced, version-policy
exemptions removed, 410 for rotated visit links, booking-aware portal bells, all suites, docs, load re-run). Details and every report:
[hardening/STATUS-after-phase5.md](hardening/STATUS-after-phase5.md); release notes: `CHANGELOG.md`.

## Known open items (honest list)

- **Throughput after the hardening round (bisected and fixed, `docs/PERFORMANCE.md` "Regression fix").** Most of the reported 30–55 % was
  the box being slower on the day of the re-run; side by side with the baseline commit the pipeline cost 5–20 % (five-command rate limit,
  budget wrappers on every Redis call, Redis budgets that fired on event-loop lag and sent requests to the database, per-request metric and
  JWT key-ring bookkeeping) and is fixed. Still open: `/bookings/:id` and `/bookings/:id/ledger` are 20–30 % slower than before the round
  (richer detail payload, same query count); `@fastify/under-pressure` can latch into 503-for-everything under sustained saturation; the
  `/search` out-of-band statement cancel can hit a neighbouring query on the same pooled connection.
- **Infrastructure follow-ups:**
  - grant `kkt_app` read on `drizzle.__drizzle_migrations` (until then the backup manifest's schema version is null);
  - set `DEPLOY_ID` from the deploy pipeline;
  - choose `DOCS_PUBLIC` per environment;
  - the production Compose stack, Caddy and PgBouncer have not been run end to end here (no Docker daemon).
- **Not built yet:**
  - the worker has no health or heartbeat port;
  - Hindi (Devanagari) text in PDFs needs a Noto font package;
  - `PARTITIONING_ENABLED`, `JOB_BACKOFF_MS`, `PDF_WORKER_*` and `SHUTDOWN_*` are read straight from the environment instead of the validated config.
- **Product decisions:** listed at the end of `docs/hardening/integrate-crosscut.md`:
  - erasure does not scrub ticket text or audit snapshots;
  - a MANUAL other-charge line that was never demanded does not block handover;
  - the in-flight login guard is per process;
  - an idempotency takeover after 60 s can run a still-alive slow request twice.
- Native iOS/Android builds of the portal were not run here (no simulator); the web export is verified.
- Open notes from browser QA are listed at the end of each `docs/qa/*.md` (e.g. ISR list pages can be stale for up to 60 s after a CMS toggle; one transient ERP axe `target-size` hit while a toast covers the cheques table).
