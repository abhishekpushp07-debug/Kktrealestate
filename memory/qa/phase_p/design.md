# Phase P — design notes (Royal v2: ink-950 shell · warm-50 surfaces · gold accents · tabular ₹)

## P1 Customer 360 — `/customers/{id}?tab=…`
**Job**: one screen answers "who is this, what do they owe, what happens next, what did we send them".
**Layout** (12-col, max-w 1440): Hero card (full width) → key-number strip (6 tiles, equal width, 4 on tablet) → sticky tab bar (top-0 under shell header, backdrop-blur warm-50/90) → tab body. Right rail disappears: everything is a tab so nothing competes for attention; Overview is the curated "rail".
**Hierarchy**: name (display 28px) > CUST number + chips (12px pills) > quick actions (icon buttons, labels on ≥xl). Tiles: label 11px upper · value 22px tabular · hint 11px (oldest-days / delta). Overdue tile turns brick only when > 0; Advance sage when > 0; never colour-noise.
**Interactions**: tabs URL-synced (`?tab=ledger`), keys `1–9,0,-` switch tabs, `/` focuses the in-tab search, `Esc` clears. Quick actions: call = `tel:`; copy phone (toast "Copied"); WhatsApp `wa.me/91…`; email `mailto`; Post payment → existing PostPayment sheet; Generate document → `/documents?customer_id=`; Add note → CommSheet; New ticket → `/service/new?customer_id=`; Schedule visit → `/site-visits/new?customer_id=`. All numbers come from one composite `GET /customers/{id}/panels` (adds `summary`, `next_due`, `demands`, `receipts`, `generated_documents`, `tickets`, `construction`) so the page settles in one paint.
**States**: skeleton tiles with fixed heights (no layout shift); empty tab = EmptyState with the one next action (e.g. "No bookings yet → New booking"); error = inline brick banner with retry, hero still renders from `/customers/{id}`. Print: `@media print` hides tab bar/actions, Overview + key strip print on one A4.
**Keyboard**: tablist roving focus; Enter on booking card opens; `p` = Post payment when permitted.

## P2 Documents — `/documents` (Generate · Bulk · Register)
**Job**: produce any customer-facing PDF deterministically, prove what was sent, re-download forever.
**Layout**: Segmented header (Generate | Bulk | Register) with KPI strip (generated today · this month · awaiting send · shared links active). Generate = 3-step left rail (Who → What → Preview) with the PDF iframe on the right (sticky, 60% width) — the preview *is* the output; no surprises on download. Bulk = filter bar → selectable table (shift-range) → sticky footer "N selected · Σ ₹ · Merge PDF / ZIP / Mark sent". Register = dense table (type chip, number, customer link, booking, project/tower, by/at, sent chip) + right-side History sheet.
**Interactions**: dependent dropdowns Project → Tower → Booking (search by name/CUST/booking) are dropdown-first; document type pills reveal only the inputs they need (receipt picker / demand multi-pick / period presets). Share = 15-min signed link copied to clipboard, audited (`document.shared`). Mark as sent = channel pill + note, writes `sent` on the register row. > 50 docs → async job with toast + Exports page link.
**States**: preview skeleton = A4 grey card with pulsing lines; errors from the builder shown in the preview pane (never a toast only); empty register → "Generate your first document".
**Letterhead**: Masters → Company (name, address, phone, email, GSTIN, RERA, logo, signatory name/designation, footer note) feeds `BrandedDoc`; every PDF shows the same header/footer; History on the company record.

## P3 Demand register — `/demands`
**Job**: see every rupee raised, by day/project/tower, with why, paid and balance; act (print, remind, void, add manual).
**Layout**: KPI strip (Raised today · this month · Due this week · Overdue ₹/count · Collection %) → control bar (date basis switch Raised/Due, presets, project/tower/stage/plan/status/source/bucket, customer search) → month calendar strip (one cell per day: raised ₹ small, bar height = relative) → grouped table DAY ▸ PROJECT ▸ TOWER with group header rows carrying totals (Cash · Account · Other · Total · Paid · Balance) and chevrons; groups default collapsed beyond the first day. Row: number · date · due · customer (link) · booking · flat · "why" (plan · stage · % · trigger) · Cash/Account/Other · paid · balance · ageing band pill · status chip · ⋯ actions.
**Interactions**: click a calendar day → range = that day; clicking a group header toggles; `Void` opens a reason dialog (permission `demands.void`) and shows ledger effect ("Udhar −₹X on BK-…"); voided rows stay, struck-through, with "Voided · reason" and no un-void. Manual demand = sheet: project → tower → booking → charge line / installment → ₹ → due date → note, with a live "ledger effect" preview (Udhar +₹, new balance) before Save.
**States**: skeleton group rows; empty day → "Nothing raised on this day"; totals footer always visible; CSV/PDF honour the current filters; ETag on the grouped payload.
**Performance**: grouped payload is one aggregation (≤ 1 round trip) with `limit` per group + "show all N" link; calendar strip is a second cheap aggregation; both cached 30 s per filter hash.
